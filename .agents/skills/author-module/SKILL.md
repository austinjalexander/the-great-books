# Author a work module

Read `AGENTS.md`, `docs/agents/PROFILE.md`, `docs/agents/module-structure.md`, and `docs/agents/tutoring.md`. Inspect the target curriculum row, subject README, progress scope, relevant templates, and reference module. Read the reference solution key only for authoring/checking.

Use the local curriculum and resource defaults when unambiguous. Ask only for missing choices that affect the task. Distinguish a locally transcribed curriculum row from a quotation verified against the current TAC syllabus; do not invent institutional requirements or an edition in use.

Create the next numbered module in the existing subject hierarchy. Provide framing, edition/source, necessary prerequisites versus useful companions, concrete objectives, prompt-file links, and estimated time. Define the exit task, timing, permitted aids, and rubric before assessment. Use a small unaided task for a small module; preserve existing broader gates such as Euclid Book I's 60-minute test.

Keep learner summaries, discussion answers, attempts, and reflections blank. Tutor explanations and examples may be supplied but must be labeled teaching material. Separate worked keys into `solutions.md`; Latin keys also belong in a separate file. Include a learner log and dated reflection stub. Do not count file creation as mastery.

Link the module from the subject README. Link existing backward/forward modules and label future paths as planned rather than making broken links. Keep the existing work-level progress scope; add a missing unchecked entry only if necessary. Check local links, source references, prompt/key alignment, and required files. Author one representative module before scaling an unspecified large expansion.
